## Repository context

A preservation project for *Battle Engine Aquila* (2003). This public repository holds:

- a pointer page, `rebuild/README.md`, where a frozen copy of the Godot rebuild stood until 2026-11-11 (it remains at the tag
  `archive/20261111-rebuild-frozen-copy`). The rebuild is developed in https://github.com/dlprentice/onslaught-godot, which holds its
  code, tests, licence and provenance record. It aims to be 1:1 with retail from startup to exit,
  with level 100 playable to completion. `OnslaughtRebuild.Parity` is the simulation owner and
  `OnslaughtRebuild.Host` the presentation owner; the earlier `OnslaughtRebuild.Core`, `Client` and `Godot` projects
  are reference material there, not a second production simulation. The CMSH mesh parser and the region and plan data that
  Toolkit tools use moved from the frozen copy to `tools/`;
- the **companion** (`companion/`), Onslaught Companion: the Godot .NET app for careers, saves, backups, settings,
  music and lore for the original game and Onslaught CE, including CE launcher settings and the steps for updating CE (the running companion contacts nothing; its build setup downloads pinned tools, see [README](README.MD#build-and-run)). The old AppCore patching
  core is gone; the file-safety and save-layout code the companion uses lives in the companion, and Git keeps the rest;
- a frozen copy of the game documentation (`reverse-engineering/`), whose home is
  https://github.com/dlprentice/onslaught-preservation, where new findings go, and our own tools.

Elsewhere: the byte-matching decompilation, the reverse-engineering authority, is public as
[onslaught-decomp](https://github.com/dlprentice/onslaught-decomp), and the native source port as
[Onslaught CE](https://github.com/dlprentice/onslaught-ce). The Ghidra checkpoint, the RE campaign
machinery, scrubbed decompiler passages and the full pre-flatten history are in the private historical maintainer archive. The native port's public source and downloads are Onslaught CE, public at
https://github.com/dlprentice/onslaught-ce, generated by the decompilation's export tool. Contributors submit proposed
commits through public forks and PRs; maintainers regenerate upstream main.
The decompilation's public export is https://github.com/dlprentice/onslaught-decomp, and the game documentation is
published at https://github.com/dlprentice/onslaught-preservation. [`GOAL.md`](GOAL.md) states the outcomes, [`PROGRAM.md`](PROGRAM.md) the work
queue, [`CURRENT_CAPABILITIES.md`](CURRENT_CAPABILITIES.md) what is demonstrated, and
[onslaught-godot's parity record](https://github.com/dlprentice/onslaught-godot/blob/main/rebuild/PARITY.md) the rebuild's
current milestones and measured parity.

## Project progress and documentation

[GOAL.md](GOAL.md) owns David's outcomes and the definition of progress; [PROGRAM.md](PROGRAM.md) owns the dated
cross-project chart and work queue; [CURRENT_CAPABILITIES.md](CURRENT_CAPABILITIES.md) owns demonstrated Toolkit
capability and limits. CE and the Godot rebuild own their detailed evidence and release status. A handoff is a dated continuity
snapshot, not a second roadmap: check current refs, claims and evidence before relying on it.

Report experiments, integrated source, released packages and real-player/platform acceptance separately. A passing
synthetic test, a branch or a byte match is evidence within its stated scope, not automatic feature completion.
Update the existing owner when a material milestone changes; preserve historical evidence rather than creating
competing live status files. Before new work, check applicable prior results and share relevant findings between lanes;
repeat checks only for changed inputs, failures or unresolved risks. Report failures and open gaps without invented
percentages, and follow the user's current priorities.

## Recording tool outcomes

Record consequential tool outcomes in existing private notes with time, action scope, returned status or reason and
known effects, keeping observations separate from interpretations. Fresh evidence can correct an interpretation without
erasing the original observation.

## The rebuild's determinism contract

The rebuild now lives in [onslaught-godot](https://github.com/dlprentice/onslaught-godot); this contract binds its
simulation wherever that work happens:

- The rebuild's simulation (`OnslaughtRebuild.Parity`) is deterministic given its inputs: the tape, the retail data
  and options files it reads as the game does, and the virtual clock. It never reads wall time, locale, environment or
  thread scheduling, and it has no presentation, process, network or GPU dependency (the earlier `Core`'s stricter
  contract is [DETERMINISM.md](https://github.com/dlprentice/onslaught-godot/blob/main/rebuild/DETERMINISM.md) in onslaught-godot). Tests compare it with recorded references Present by
  Present; missing references, empty selections and new skips are not passes.
