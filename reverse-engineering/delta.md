## Evidence and relation vocabulary

### Evidence planes

| Grade | What it can establish | What it cannot establish by itself |
| --- | --- | --- |
| **DATA-MEASURED** | File existence, bytes, framing, hashes, counts, identifiers, authored relationships | Which executable branch consumes the file, or runtime behavior |
| **EXECUTABLE-BYTES** | Code, tables, ABI, constants, imports, RTTI, callsites, and field access read from the named executable | Depot identity, a branch being reached, or final audiovisual/gameplay output |
| **ANALYST-METADATA** | Current Ghidra functions, names, comments, tags, types, and note state | That a semantic label is correct or that a byte range is a true function |
| **RUNTIME** | Observed behavior and causality on the exact copied specimen/path | Untaken branches, other levels, or unobserved populations |
| **SOURCE** | Developer names, ownership, algorithms, layout intent, target-conditional implementations | Exact baseline revision, selected compile branch, ABI, or baseline behavior |
| **REBUILD** | What the current reconstruction implements and its tests assert | What the hashed baseline did |
| **INFERRED** | A joined explanation that fits stronger evidence | Proof; a material inference needs a falsifier |
| **UNKNOWN** | A bounded gap and the observation needed to close it | Permission to guess |
| **HISTORICAL** | Provenance and prior state | Current truth |

### Relationship grades

| Relation | Meaning |
| --- | --- |
| **TRI-CONVERGENCE** | Data, executable, and source independently align on the same identity/shape; runtime may still be open |
| **DUAL-CONVERGENCE** | Two planes align while the third is absent or silent |
| **DELTA** | Two scoped claims materially differ; a subtype and question-specific authority must be recorded |
| **BASELINE/SOURCE DELTA** | Strong bytes from the named executable baseline differ from Stuart's supplied lineage; depot identity remains a separate provenance question |
| **PLATFORM/REVISION DELTA** | Both claims can be true because target or revision differs |
| **REBUILD DELTA** | Current implementation differs from the explicitly selected, evidence-backed contract owner |
| **DOCUMENTATION/TOOL DELTA** | A label, parser, note, or projection contradicts its stronger owner |
| **SCOPE DIFFERENCE** | Counts or claims concern different sets; combining them would create a false contradiction |
| **OPEN JOIN** | Keys align, but ownership or semantics have not been demonstrated |
| **REFUTED** | Stronger evidence has already killed the prior claim |

The bold labels such as `MECHANISM`, `TABLE`, `PARSER/GATE`, `EDGE-SPECIFIC`,
or `NAMED-SPECIMEN/SOURCE` used later are **DELTA subtypes**, not new
top-level relation grades. A mechanical ledger stores the top-level resolution
and subtype in separate fields.

### Authority depends on the question

There is no single universal winner:

| Question | Primary authority | Corroborators |
| --- | --- | --- |
| Does this exact file exist in the measured install? | Installed file ledger | Installer history/manuals only as context |
| What bytes/ABI/table are in the project baseline? | Named executable bytes | Data and source |
| What happened on this captured path? | Controlled copied runtime | Static code, data, source |
| What did this internal lineage intend or call a system? | Pinned source | RTTI, strings, data |
| What should parity reproduce? | Controlled runtime on the named copied specimen, then matching executable bytes | Source as implementation guide |
| What does the current rebuild do? | Current code plus executed focused test | Documentation is secondary |
| What may be redistributed? | Repository provenance/license owners | Similarity or file extension never decides |

Cross-source agreement increases confidence but does not change the evidence
class. Source plus decompilation is still static. A parser plus a successful
decode is still a format observation. A rebuild test is still reconstruction
evidence.

### Independence is a claim property

Three documents agreeing is not necessarily three independent observations.
Common dependence is pervasive:

- a Ghidra source-backed name may have been assigned from Stuart's source;
- an `RTTI_CONFIRMED` prefix may have been constructed from the same RTTI data
  that the grader later checks;
- a rebuild test may encode a constant copied from source or decompilation;
- a prose master may summarize the same underlying capture as another master.

Every durable claim ledger should therefore carry an `independence_group`.
Examples:

```text
exe:74154bfa:bytes
install:3d8aa45f:filesystem
source:5352a81c:text
runtime:E1436EF7:play-level100
ghidra-live:45CBA6...:metadata
rebuild:<commit+dirty-fingerprint>:test
```

Only agreement across different groups is independent corroboration. Current
Ghidra names, comments, tags, `USER_DEFINED`, note presence, fullpass
`ok/confirm`, and source-token grades are **ANALYST-METADATA** until their
semantic claim is independently tied to bytes, a baseline table,
source, or runtime behavior.

## Atom-level completeness contract

“Understand everything” needs a discrete finish line. It cannot mean “a very
large document” or “no one noticed another question.”

### The atom is a keyed claim, not a paragraph

Every claim row should contain:

```text
ClaimID
entity key
observation
specimen/hash
evidence family
independence group
scope/denominator
evidence states (one or more)
resolution state
delta subtype, if any
semantic grade
completion claim, if any
contradiction link
cheapest falsifier
current owner
last measurement date
```

Stable entity keys:

```text
FILE
  install-manifest-digest + exact relative path/case + file hash

AYA
  FILE key + zlib-member offset + nested tag path + payload offset/length

CODE
  executable hash + VA + exact body-range set + verified bytes

EXECUTABLE DATA
  executable hash + VA/range + table/record index

ANALYST METADATA
  Ghidra export hash + program identity + address + field kind

SOURCE
  source pin + path + preprocessor guard + line/signature/table index

RUNTIME
  target hash + capture id + arguments + trace/frame/event position

REBUILD
  commit + dirty fingerprint + path + test/capture identity

WORLD
  install digest + typed role (header/script/resource/Career/briefing) + world id

MISSION
  loose/packed object or event: FILE/AYA key + entity kind + name/offset
  native/opcode/datatype: EXECUTABLE DATA key + registry kind + record index/name

PHYSICS
  FILE/AYA key + statement offset/index + node offset/ordinal;
  statement family + definition key + value-family id are join attributes

CONFIGURATION
  FILE key + profile name/index + record/field offset

GOODIE
  install digest + coordinate kind (storage/script/descriptor/archive/grid/media) + id

LOCALIZATION
  FILE key + locale + unsigned DAT id/signed STF id/audio-id field

MEDIA
  FILE key + stream/record index + language/role when demonstrated

RENDER
  RUNTIME key + pass/draw index + resource/state/geometry subkey
```

Typed domain keys prevent the numeric value `232`, for example, from silently
joining a Goodie archive, storage slot, grid result, cutscene, and world.

### Orthogonal claim fields

One `status` column is insufficient. Evidence origin, conflict resolution, and
semantic depth are independent:

| Evidence state (set-valued) | Meaning |
| --- | --- |
| `MEASURED_SHAPE` | Bytes/framing/count known; semantics may remain opaque |
| `SOURCE_ONLY` | Direct source intent/algorithm without independent baseline support |
| `BASELINE_STATIC` | Direct named-executable byte/table/code result |
| `ANALYST_METADATA_ONLY` | Database/note state without independent semantic proof |
| `RUNTIME_BOUNDED` | Observed on the named target/path only |
| `REBUILD_ONLY` | Implemented/tested reconstruction state only |

| Resolution state | Meaning |
| --- | --- |
| `CONVERGED_INDEPENDENT` | Two or more independent evidence groups align |
| `DELTA_ADJUDICATED` | Scoped claims materially differ; authority and subtype are recorded |
| `OPEN_JOIN` | Keys align, but ownership/semantics are not demonstrated |
| `CONTRADICTED` | Stronger evidence refutes the active claim |
| `UNKNOWN_WITH_FALSIFIER` | Not settled; exact cheapest observation named |
| `SUPERSEDED` | Retained only to prevent regression |

| Semantic grade | Meaning |
| --- | --- |
| `OPAQUE` | Atom exists and is bounded; meaning unknown |
| `FRAMED` | Container/record boundaries are exact |
| `FIELD_TYPED` | Declared fields and opaque spans are losslessly mapped |
| `STATIC_BEHAVIOR` | Named code/table establishes a mechanism without reachability/output proof |
| `RUNTIME_BEHAVIOR` | Behavior observed on the exact target/path |
| `PARITY_DEMONSTRATED` | Declared discrete output/state contract matches the named target |
| `NOT_APPLICABLE` | Semantic interpretation is not part of this atom's declared contract |

A row may carry several evidence states, exactly one current resolution for its
scoped question, and the semantic grade appropriate to that question.
“Unknown with falsifier” is successful honest accounting. “Looks right” is not.

### Closure rule

Never use “atom-complete” as an unqualified synonym for “listed.” Report three
different bars:

**ACCOUNTED / inventory-complete for scope**

1. the exact denominator, specimen, and key-generation method are frozen;
2. every key is visited and totals regenerate from primary rows;
3. typed overlaps are joined before rollup;
4. every row has evidence/resolution/semantic fields, even when semantic grade
   is `OPAQUE`;
5. non-atomic traversal limits and discovery-open surfaces are explicit; and
6. a read-only adversary reproduces counts and load-bearing joins.

**SEMANTICALLY CLOSED for scope**

1. accounting closure is already met;
2. the declared semantic contract is explicit;
3. `OPAQUE`, partial, unsupported, and `UNKNOWN_WITH_FALSIFIER` counts are zero
   inside that contract;
4. no unresolved contradiction hides inside a settled row; and
5. every named field/mechanism has evidence at the claimed grade.

**PARITY-CLOSED for scope**

1. semantic closure is already met for the selected behavior/output contract;
2. each behavior/output claim carries controlled observation or a discrete
   state/output comparison on the named target and path;
3. byte comparison alone closes only byte/ABI/table claims, not reached
   behavior or audiovisual output; and
4. repeatability, positive control, and perturbation/noise limits are recorded.

Evidence binding applies at every bar: source claims carry pin/path/guard;
executable claims carry hash/address/range; analyst claims carry export/program/
field identity; runtime claims carry target hash, derivation, arguments/profile,
instrumentation, capture/frame/event position, scope, and positive control;
rebuild claims carry commit plus content-sensitive dirty fingerprint and an
actually executed focused test; provenance and redistribution state are
explicit.

Reserve `atom-complete` only for a precisely named semantic or parity scope that
meets the corresponding bar. No global “game understood X%” is allowed. Report
separate accounting, semantic, and parity results for files, chunks, typed
content/worlds, code, source, reconstruction, and runtime captures.

### Builder/adversary loop

For each denominator-frozen ledger scope:

1. Builder extracts exact sets and populates rows.
2. Read-only adversary independently regenerates counts/set joins and samples
   or re-reads load-bearing rows.
3. Every difference is resolved or downgraded to
   `UNKNOWN_WITH_FALSIFIER`.
4. Run a second complete pass over the same discrete bar.

The critic must be able to return `UNSCORED`. Continuous visual/audio similarity
can locate defects but cannot be the termination gate. When improvement reaches
the measured noise floor, change instruments rather than fit parameters.

### Minimum verification gates for a delta update

- all three input-master hashes recorded;
- all named specimen hashes match;
- file/address/source keys resolve;
- Markdown links and header contract pass;
- set totals and differences regenerate;
- cited bytes are reread from the named executable;
- no historical percentage is rolled forward;
- runtime captures include positive controls;
- source target guards are recorded;
- the frozen survey state is stated rather than implied to be live;
- focused tests are actually run when implementation claims change;
- retail/local assets and machine-local evidence remain outside tracked public
  artifacts.

## Closing synthesis

The three masters do not reveal three versions of the same list. They reveal
three layers of one system:

```text
DATA says which authored entities and payloads exist.
EXECUTABLE BYTES say which mechanisms and tables this baseline contains.
STUART says how a close internal lineage named and designed many of them.
RUNTIME decides reached behavior.
REBUILD records what has actually been reconstructed.
```

The most valuable discoveries occur where stable keys cross layers:
Mission names into handler addresses, Physics ids into destination fields,
configuration fields into player damage, Goodie-state/media keys into
archives/cutscenes,
SFX recipes into XAP identities and device state, and world ids into Career,
scripts, resources, and briefings.

The most dangerous mistakes occur when those layers are flattened: treating a
source body as baseline behavior, a Ghidra label as a byte fact, a wrapper parse
as semantic support, a local install as a depot manifest, a proxy capture as
rebuild parity, or an executed-looking test declaration as a passing gate.

The project now has enough structure to advance the currently identified finite
surfaces by enumeration, while registry, runtime, recursive-format, and rebuild
feature discovery remain open. The next bounded units include:

  recursive tag denominator pending

  registry-of-registries discovery open
